Start og tjek

Vaultwarden starter sammen med resten af stakken. Den har ingen porte udadtil og nås kun gennem nginx.

task docker:site:up
curl https://vault.bibleguessr.srv/alive
# "2026-09-29T20:14:02.113Z"

Logs:

docker logs -f bibleguessr-production-vaultwarden-1

Konfiguration

To filer, oprettet af scripts/env-init.sh:

FilVariabelEksempel
env/nginx.envDOMAIN_VWvault.bibleguessr.srv
env/vaultwarden/vaultwarden.envDOMAINhttps://vault.bibleguessr.srv
SIGNUPS_ALLOWEDfalse
ADMIN_TOKEN'$argon2id$v=19$…' (tom = /admin lukket)

Efter en ændring i env-filen skal containeren genskabes. docker restart læser ikke filen igen.

task docker:site:up
docker inspect -f '{{range .Config.Env}}{{println .}}{{end}}' \
  bibleguessr-production-vaultwarden-1 | grep SIGNUPS
# SIGNUPS_ALLOWED=false

Admin-panel

1. Lav en hash af et langt, tilfældigt password:

docker exec -it bibleguessr-production-vaultwarden-1 /vaultwarden hash
# ADMIN_TOKEN='$argon2id$v=19$m=65540,t=3,p=4$...'

2. Sæt hele linjen ind i env/vaultwarden/vaultwarden.env, med de enkelte anførselstegn, og kør task docker:site:up.

3. Åbn https://vault.bibleguessr.srv/admin og log ind med passwordet, ikke hashen.

Opret brugere

Admin kan ikke sætte en brugers password. Master-passwordet laves altid på klienten, fordi det er det, der krypterer vaulten. Du inviterer i stedet mailadressen, og brugeren opretter selv kontoen.

Eksempel uden SMTP:

  1. /admin → Users → Invite User → theodor@example.dk
  2. Åbn https://vault.bibleguessr.srv → Create account med præcis theodor@example.dk
  3. Vælg master-password. Kontoen er aktiv, selvom SIGNUPS_ALLOWED=false.

Master-passwordet kan ikke nulstilles. Glemmer du det, er vaulten tabt.

Klienter

Brug de officielle Bitwarden-klienter (browserudvidelse, desktop, mobil). Vælg Self-hosted på login-skærmen:

Server URL: https://vault.bibleguessr.srv

Mobil virker kun mod produktionsdomænet. Telefonen kan ikke slå .srv op og stoler ikke på dev-certifikatet.

Test

Routing-testen kører nginx-configen mod en mock. Den dækker host-navn, HTTP→HTTPS, WebSocket, X-Forwarded-For, store vedhæftninger, login-rate-limit og at tokens ikke logges.

task docker:nginx:test

Manuelt: ret et element i web-vaulten. Opdateres det med det samme i browserudvidelsen, virker live-sync over WebSocket.

Faldgruber

SymptomÅrsag og løsning
Registration not allowed or user already exists Oprettelse er slået fra. Invitér mailen via /admin, eller sæt midlertidigt SIGNUPS_ALLOWED=true og genskab containeren.
ADMIN_TOKEN is enabled but has an empty value Forventet, når ADMIN_TOKEN er tom. /admin er så lukket.
Ændring i env-filen har ingen effekt Containeren er ikke genskabt, eller der er gemt indstillinger i admin-panelet. Save dér skriver /data/config.json, som vinder over env. Brug Reset defaults.
Certifikatfejl efter task dev:host:bootstrap Nginx bruger stadig de gamle certifikater: docker exec bibleguessr-production-nginx-1 nginx -s reload
429 på login eller /admin Nginx rate-limit (zone vault_login). Vent et øjeblik.
