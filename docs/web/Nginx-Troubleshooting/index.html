nginx troubleshooting

Cheat sheet for when nginx in production is down, restarting, or answering with errors. Work top to bottom. Run everything from the project root on the server.

1. Triage: is it running?

docker ps -a --filter name=bibleguessr-production --format 'table {{.Names}}\t{{.Status}}\t{{.Image}}'
# bibleguessr-production-nginx-1   Restarting (1) 4 seconds ago   isuperman/bibleguessr-nginx:0.0.4
StatusMeaningGo to
Restarting (1)nginx refuses the config at startup and restart: unless-stopped loops it2
Exited / missingStopped, or compose up failed before start (ports, env, image)7, 9

Restart count and last exit code:

docker inspect -f '{{.RestartCount}} restarts, exit {{.State.ExitCode}}' bibleguessr-production-nginx-1

2. Read the error

nginx writes startup errors to stderr, so they are in the container log. Look for [emerg].

docker logs --tail 50 bibleguessr-production-nginx-1 2>&1 | grep -E 'emerg|alert|crit|error'
# nginx: [emerg] cannot load certificate "/etc/letsencrypt/live/bibleguessr.uk/fullchain.pem" ...

Follow live traffic and errors:

docker logs -f --since 5m bibleguessr-production-nginx-1

4. Test the config without downtime

Container is up: test what is on disk, reload only if it passes. A failed reload keeps the old config running.

docker exec bibleguessr-production-nginx-1 nginx -t && \
docker exec bibleguessr-production-nginx-1 nginx -s reload
# nginx: configuration file /etc/nginx/nginx.conf test is successful

Container is down or looping: run nginx -t in a one-off container with the same mounts. compose run publishes no ports, so it does not clash with anything.

docker compose --env-file env/app.env --env-file env/nginx.env --env-file env/letsencrypt.env \
  --env-file .env -p bibleguessr-production run --rm --no-deps nginx nginx -t

Dump the full effective config (all includes merged):

docker exec bibleguessr-production-nginx-1 nginx -T | less

Routing regressions: task docker:nginx:test runs the config against a mock API and never touches the running stack.

5. Certificates

Every ssl_certificate path must exist, or nginx will not start at all, for any site.

# Which certs does the config expect?
grep -h ssl_certificate nginx/conf.d/*.conf

# Which certs exist?
sudo ls /etc/letsencrypt/live/
# bibleguessr.uk  kforkode.dk  vault.kforkode.dk  README

task letsencrypt:certbot:5-verify-certs

Expiry date and names on a cert:

sudo openssl x509 -in /etc/letsencrypt/live/bibleguessr.uk/fullchain.pem -noout -enddate -ext subjectAltName
# notAfter=Dec 28 10:12:00 2026 GMT
# DNS:bibleguessr.uk, DNS:www.bibleguessr.uk

What the server actually serves:

echo | openssl s_client -connect 127.0.0.1:443 -servername bibleguessr.uk 2>/dev/null \
  | openssl x509 -noout -subject -enddate

The folder name under live/ is what counts, and it must equal DOMAIN_BG / DOMAIN_VW in env/nginx.env. A cert issued with -d bibleguessr.uk lives in live/bibleguessr.uk/. Reissuing can create live/bibleguessr.uk-0001/, which nginx will not find.

6. Generated config

nginx reads nginx/conf.d/*.conf, which is rendered from *.conf.template. Some generated files are tracked in git with dev domains, so a git pull, git checkout or a plain docker compose up (skipping the task) can leave nginx with bibleguessr.srv cert paths.

# Are the generated files the dev versions from git?
git status --short nginx/
grep -h server_name nginx/conf.d/2*.conf nginx/conf.d/3*.conf
# server_name bibleguessr.uk www.bibleguessr.uk;   ← good
# server_name bibleguessr.srv www.bibleguessr.srv; ← stale, regenerate

# Any variable left unsubstituted?
grep -n '\${' nginx/conf.d/*.conf

# Values used for substitution
grep -E '^DOMAIN_(BG|VW)=' env/*.env

Regenerate and restart (always through the task, which renders the templates first):

task docker:nginx:generate-conf
task docker:site:up

7. Ports 80/443

sudo ss -ltnp '( sport = :80 or sport = :443 )'
docker ps --filter publish=80 --filter publish=443 --format '{{.Names}}'
# nginx-nginx-1   ← the temporary ACME nginx from initialize-certs/

Stop the ACME nginx after issuing certs, then start the stack:

task letsencrypt:acme:6-nginx-down
task docker:site:up

Top status codes and client IPs in the last 10 minutes:

docker logs --since 10m bibleguessr-production-nginx-1 2>/dev/null | awk '{print $9}' | sort | uniq -c | sort -rn | head
docker logs --since 10m bibleguessr-production-nginx-1 2>/dev/null | awk '{print $1}' | sort | uniq -c | sort -rn | head

Field positions depend on the realip format in includes/log-formats.conf. Adjust $9/$1 if needed.

9. Recover

  1. Read the [emerg] line (2).
  2. Fix the template, env file or cert. Never hand-edit a generated .conf.
  3. task docker:nginx:generate-conf
  4. Test with compose run … nginx -t (4).
  5. task docker:site:up
  6. Verify: docker ps shows Up, and the curl in 8 returns 200.

Roll back to the last working config if you are stuck:

git log --oneline -5 -- nginx/
git diff HEAD~1 -- nginx/          # what changed?
git checkout <good-commit> -- nginx/includes nginx/conf.d/*.template
task docker:site:up

Do not git checkout the generated conf.d/*.conf files on the server. They contain dev domains. Always regenerate them.
